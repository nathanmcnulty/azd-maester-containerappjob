# Viewer content qualification policy

This converter accepts a report only when it is an exact instance of the approved Maester 2.2.0 HTML template. The converter pins the template bytes to SHA-256 `A7B8DAE3D5932C3096FA98709AAAB9E9C1EBBFB83B5519E524B734EC751E3416`; the reviewed Maester 2.2.0 package has SHA-256 `8C8A9757771177BD89785262E6B38385CF5E5C19BB799E4399E77F6439AD699C`. Updating either source requires a new review and browser qualification.

`ConvertTo-MaesterViewerReportProjection` rejects empty or oversized byte inputs before hashing or decoding, then validates the template hash before interpreting it. It requires strict UTF-8 without a BOM, exact prefix and suffix boundaries, and at most one writer-added LF or CRLF. `EndOfJson` identifies the unique insertion boundary in the trusted template; it is not required in the report data because supported producers can append properties after it or omit it. The embedded value must be a JSON object. JSON parsing rejects duplicate properties, comments, trailing commas, excessive depth, excessive token counts, and oversized input. Parser failures return one closed error without report property names or parser details. The converter preserves the parsed JSON text as data and embeds it through `JSON.parse` using the .NET safe JavaScript encoder. Report, template, JSON, encoded-string, and final-output allocations have explicit limits. `Assert-MaesterViewerReportProjection` extracts only the bounded JSON string from this exact patched-template shape, rebuilds it with the same fixed converter, and requires byte-for-byte equality; it accepts no template hash override or validation callback.

The converter applies four exact, version-bound changes to the trusted template code before embedding report data:

- ReactMarkdown's shared default URL transform returns no URL. Markdown links and images remain as formatted text but have no external `href` or `src`.
- The help-link control is disabled, so report-provided `HelpUrl` values are retained only as inert JSON data.
- The custom tenant banner source is disabled, so report-provided banner values are retained only as inert JSON data.
- The fixed external favicon is removed. The template's embedded static Maester logo remains available.

The function adds a first-in-`head` meta Content Security Policy bound to the reconstructed inline script hash. It denies default, connection, media, object, frame, worker, base, and form sources; permits the reviewed inline styles; and permits only data URLs for images and fonts. A meta policy cannot enforce framing or sandbox controls, so those remain response-header responsibilities for the loopback worker and proxy integration.

This is a hash-bound converter for one reviewed template, not a general HTML sanitizer. Report data cannot replace the trusted markup, paths, URL behavior, configuration, or approved template. The default-off runner qualifies generated reports before any projection or legacy report write. The projection publisher rejects unqualified bytes before its first store call, and the reader independently requalifies downloaded bytes after protocol hash checks. The worker image contains only the hash-verified template extracted from the locked Maester package at build time; its entrypoint has no template path override. Deployment defaults remain unchanged.

The exact public converter passed a local Chrome 155.0.8059.82 browser gate against the locked template and raw synthetic reports, including the normal `OutputFiles` metadata after the template sentinel. Two fixtures each exercised details, Markdown preview, and print: JSON values remained equivalent; script/event markers stayed inert; report-supplied inline, reference, automatic, and image URLs had no destinations; help controls and custom banners stayed inactive; and all six views recorded zero external requests, page errors, console errors, failed requests, or CSP violations. This is fixture-bound content evidence, not live tenant collection, end-user access, or deployment acceptance. The retained prototype evidence has a deliberate chronology: R4 proved safe JSON embedding and CSP compatibility while retaining the favicon; R5 added CSP-violation capture and exposed the blocked favicon and Markdown resources; R6 introduced URL inerting and favicon removal; R7 exercised details, Markdown preview, and print for ordinary and script-boundary reports with zero external resource attributes, requests, page errors, console errors, or CSP violations.

The meta-policy constraints follow the [CSP specification](https://www.w3.org/TR/CSP/). HTTP framing controls, deployment wiring, release dependency closure, and fresh validation of any changed template remain separate gates.
